## 背景结论（已查清）

1. **AI 对话不能复制**：`ChatMessageItem.tsx` 完全没有复制能力（无 CSS 拦截，纯 UI 缺失）。项目已有现成模式可复用：`SessionMessageItem.tsx:62-78` 的 hover 复制按钮 + `src/lib/clipboard.ts` 的 `copyText()`（Tauri invoke 优先、浏览器 clipboard 兜底）+ sonner toast。
2. **测速要按"高级选项的上游格式"**：Rust 后端（HEAD 中）探测时本来就按 `meta.apiFormat`（openai_chat / openai_responses / anthropic / gemini_native）构造请求体和端点。真正的 bug 在前端：`ProviderForm.tsx:602` 和 `:1818` 对 **codex 的兜底默认写成了 `"openai_responses"`**，而 Rust 侧 `model_probe.rs` 对未标注格式的 app 默认是 `OpenAiChat`。老数据/新建未标注格式的第三方供应商，保存表单时会把 `meta.apiFormat` 写成 responses，导致探测请求按 Responses 格式发给 chat 兼容上游而失败。
3. **OpenAI 默认**：同上——默认应为 `openai_chat`（与后端一致的兜底）。
4. 附注（不列入本次修改，避免误改）：`ProviderAdvancedConfig.tsx` 的"高级选项"实际是**计费配置**；端点测速 `EndpointSpeedTest.tsx` 只测 URL 延迟、与上游格式无关，属于设计如此，不动它。
